# Card Catalog — трекер задач

Портфолио-проект: FastAPI-бэкенд (слоистая структура) + фронтенд без
фреймворков (HTML/CSS/JS раздельно), который FastAPI отдаёт сам.
Тема оформления — библиотечная картотека: карточки с перфорацией и
штампом DONE.

## Структура

```
CardCatalog/
├── backend/
│   ├── app/
│   │   ├── main.py       — точка входа: поднимает FastAPI, роуты, статику
│   │   ├── database.py   — подключение к SQLite через SQLAlchemy
│   │   ├── models.py     — ORM-модель Task (описание таблицы)
│   │   ├── schemas.py    — Pydantic-схемы валидации
│   │   ├── crud.py       — вся работа с БД
│   │   └── routers.py    — HTTP-роуты
│   └── requirements.txt
├── frontend/
│   ├── index.html
│   ├── style.css
│   └── app.js
├── .gitignore
├── LICENSE
└── README.md
```

## Запуск (один сервер — и API, и интерфейс)

```
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Открой в браузере: **http://localhost:8000**

FastAPI сам отдаёт `frontend/index.html`, `style.css`, `app.js` —
отдельно запускать фронтенд не нужно. API при этом продолжает
работать на своих путях:

- GET    /api/tasks       — список задач
- POST   /api/tasks       — создать задачу
- PATCH  /api/tasks/{id}  — обновить задачу
- DELETE /api/tasks/{id}  — удалить задачу
- GET    /api/health      — проверка живости сервера
- GET    /docs            — автоматическая документация API (Swagger UI)

SQLite-файл `tasks.db` создаётся автоматически при первом запуске —
его не нужно создавать руками, схема описана в `app/models.py`.

## Как это устроено технически

В `main.py` API-роуты (`/api/...`) регистрируются первыми через
`include_router`, а уже после них весь фронтенд монтируется через
`StaticFiles(directory=..., html=True)` на корень `/`. FastAPI сначала
проверяет совпадение с зарегистрированными API-роутами, и только если
путь не подошёл ни под один из них — отдаёт статический файл. Поэтому
`/api/tasks` уходит в бэкенд-логику, а `/`, `/style.css`, `/app.js` —
отдаются как обычные файлы.

## Разработка при активной перегрузке фронтенда

Если часто редактируешь только фронтенд и не хочешь перезапускать
uvicorn ради каждого изменения в CSS/JS — можно временно вернуться к
раздельному запуску: держать бэкенд на 8000, а фронтенд открывать
через `python -m http.server 5500` из папки `frontend/` отдельно.
Оба варианта рабочие, единый сервер просто удобнее для финальной
проверки и деплоя.

## Деплой

Так как это теперь один процесс — деплоится он и как один сервис:

- **Railway** — просто разверни папку `backend/` целиком (там же
  лежит `frontend/` на уровень выше — учти это при настройке root
  directory в Railway, либо скопируй `frontend/` внутрь `backend/`
  перед деплоем, если платформа ожидает всё в одной директории)
- Для реального продакшена стоит перейти с SQLite на Postgres —
  Railway выдаёт его бесплатно на старте, меняется одна строка в
  `database.py`
